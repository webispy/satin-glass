# Glass Layer 디자인 언어 (0.1)

> 디자인 언어에서 실제로 정한 값과 그 이유를 정리한다.

## 1. 주요 결정

| 영역 | 결정 | 이유 |
|---|---|---|
| 재질 | **빛을 따르는 유리**: 빛 쪽만 밝은 그라디언트 테두리 + 안쪽 깊이 그라디언트 + 포인터를 따르는 하이라이트 + 배경색이 스며드는 틴트(선택) | 모든 브라우저에서 같은 모습. 요소별 이미지를 만들 필요가 없음 |
| 모양 | **고정 반경**: 컨트롤 12 · 카드 16 · 바/패널 22 · 시트 28. 캡슐은 칩, 토글, 배지만 | 정보 밀도, 크기마다 일정한 모서리 |
| 바 | 화면 끝에서 12px 띄운 떠 있는 바, 반경 22 | 바와 내용이 겹쳐도 화면 끝과 구분됨 |
| 색 | **OKLCH 자체 팔레트** 11색 × 11단계. 강조색 iris(보라 쪽 파랑) | 대비를 예측할 수 있는 단계 |
| 글꼴 | **Pretendard** → 시스템. 본문 16px | 재배포 가능, 한글 품질 |
| 아이콘 | 라이브러리는 자체로 그린 최소 글리프만 포함. 앱은 Lucide 등을 쓴다 | 라이브러리를 가볍게. 아이콘 세트는 앱이 고른다 |
| 탭 선택 | **물방울 다리**: 선택 표시가 바 안에서 앞쪽 끝이 먼저 늘어나 다음 탭까지 이어졌다가 모임. 끌면 바 안에서 손가락을 따라감 | 세그먼트 컨트롤·스위치와 같은 물방울 언어 |
| 팝업 등장 | **피어남(bloom)**: 앵커에 가장 가까운 점에서 앵커 반대쪽으로 펼쳐짐(메뉴는 가로 0.6 · 세로 0.3배에서 시작). `pop` 스프링으로 ~110ms 만에 90 %, 한 번 넘쳤다 자리 잡음. 닫힐 때는 150ms 만에 앵커 쪽으로 접혀 사라짐. transform·opacity만 사용 | 합성기에서만 실행, 빠른 체감 |
| 눌림 | 살짝 들어감(0.965배) + 손가락 아래로 빛이 모임 | 물리적인 감각 |
| 스위치 | 탭 바와 같은 물방울: 양 끝이 각자 스프링으로 움직여(앞쪽 snappy, 뒤쪽 smooth) 가는 쪽으로 늘어났다 모임. 켤 때·끌 때 똑같고 레일을 벗어나지 않음. 누르면 갈 쪽으로 6px 뻗음. 끌다가 위아래 48px·좌우 120px 넘게 벗어나면 놓아 줌 | 일관성, 오조작 방지 |
| 모션 | **이름 붙은 스프링 4개**(snappy · smooth · bouncy · gentle). CSS는 `linear()` 이징, 손가락 동작은 같은 값의 JS 스프링 | 일관성, 성능 |
| 컨텍스트 메뉴 배경 | 어둡게만 하고 항목은 1.03배로 떠오름 | 성능 |
| 스크롤 가장자리 | 색 그라디언트만 | 성능 |

## 2. 토큰

- **색**: `--gl-<hue>-<step>`(원시) + `--gl-<semantic>`(테마별). 빌드할 때 대비를 검사하고, 기준에 못 미치면 빌드가 실패한다.
  - 기본 테마: 본문 7:1, 보조 텍스트 4.5:1, 강조 텍스트 4.5:1
  - 고대비 테마: 기준을 한 단계씩 올림(본문·보조·강조 텍스트 모두 7:1)
- **재질**: `--gl-glass-fill(-strong|-subtle|-clear)`, `--gl-glass-rim-lit/-shade`, `--gl-glass-depth`, `--gl-glass-highlight`, `--gl-blur(-strong|-subtle)`
- **모션**: `--gl-spring-<name>`(linear 이징) + `--gl-spring-<name>-duration`

| 스프링 | 응답 | 감쇠 | 정착 시간 | 쓰임 |
|---|---|---|---|---|
| snappy | 0.26s | 0.86 | ~0.33s | 탭, 토글, 눌림 (calm 값; 6장의 성격별 값 참고) |
| smooth | 0.36s | 1.0 | ~0.6s | 선택 이동, 제자리 복귀 |
| bouncy | 0.42s | 0.72 | ~0.68s | 대화상자, 토스트 |
| gentle | 0.5s | 1.0 | ~0.85s | 시트, 화면 전환 |
| pop | 0.3s | 0.64 | ~0.5s | 메뉴·팝오버 피어남 (90 %까지 ~115ms, 8 % 넘침) |

## 3. 성능 규칙

1. **움직이는 속성:** 애니메이션은 transform과 opacity만 움직인다.
   - 예외는 탭·세그먼트 표시기의 `width` 하나다. 배경 필터 없는 작은 요소이고, `contain: layout` 안에 있다.
2. **블러 레이어 수:** 화면당 블러 레이어는 3개까지 쓴다(바, 패널 하나, 시트 하나). 전체 화면 블러는 쓰지 않는다.
3. **포인터 빛:** 포인터 이벤트는 창 하나에서만 받고 rAF로 묶는다. 요소 위치는 스크롤·크기 변화가 있을 때만 다시 잰다. 하이라이트는 합성 레이어의 transform으로만 움직인다.
4. **제스처 상태:** 끌기·눌림 상태는 React 상태나 data 속성에 둔다. 클래스에 두면 다시 그릴 때 지워진다.
5. **유리 표면은 스스로 스크롤하지 않는다.**
   - **규칙:** 유리는 항상 바깥에서 잘라내고(`overflow: hidden`), 스크롤은 안쪽 요소가 맡는다. 사이드바는 `.gl-sidebar__scroll`, 대화상자는 `.gl-dialog__scroll`, 메뉴는 `[data-gl-content]`가 스크롤한다.
   - **이유:** 포인터 하이라이트는 유리 안에 절대 위치로 놓인 요소다. 유리가 스스로 스크롤하면, 하이라이트가 가장자리로 갈 때 스크롤 영역이 커져서 스크롤바가 생긴다.
   - **검사:** e2e가 모든 문서 페이지에서 스크롤하는 유리 표면이 없는지 확인한다.
6. **제스처 처리:** 끌기는 시작부터 끝까지 창 단위로 듣는다. 그래서 포인터가 어디서 떨어지든 제스처가 반쯤 끝난 채로 남지 않는다. 문턱(threshold)이 있는 끌기는 실제로 끌기가 시작될 때 포인터를 붙잡는다. 누르는 순간 붙잡으면 시트 머리의 취소·완료 같은 안쪽 버튼의 클릭이 사라지기 때문이다.

측정 결과는 Chromium, CPU 4배 감속 기준이다(`tests/e2e/perf.mjs`).
- **통과:** 탭 이동, 메뉴, 대화상자, 시트, 토스트, 스위치, 세그먼트, 포인터 빛, 유리 바 아래 스크롤에서 프레임 드롭 없음
- **알려진 예외:** 페이지에서 처음 하는 동작은 코드와 스타일 준비 비용 때문에 첫 프레임이 1번 늦을 수 있다. 시트 첫 열기는 약 70ms였고, 두 번째부터는 약 8ms다.

## 4. 접근성

- **키보드:** 모든 컴포넌트를 키보드로 조작할 수 있다. 탭·세그먼트는 방향키로 이동하고, 메뉴는 방향키·Home/End·첫 글자 찾기를 지원한다. 오버레이는 Esc로 닫는다. 대화상자와 시트는 포커스를 가두고, 닫히면 포커스를 원래 자리로 돌려준다.
- **Safari 대응:** Safari는 Tab으로 버튼을 건너뛰는 게 기본 설정이라, 포커스 가두기가 Tab 이동을 직접 처리한다. 버튼 클릭으로 포커스가 가지 않는 Safari 동작 때문에, 메뉴는 닫힐 때 포커스를 앵커로 돌려준다.
- **시스템 설정:** 시스템의 동작 줄이기, 투명도 줄이기, 고대비, 강제 색상 모드를 따른다. `createTheme`으로 직접 지정할 수도 있다.
- **앱 안에서 줄이기:** VDI·원격 데스크톱처럼 화면을 스트리밍하는 환경에서는 애니메이션과 블러가 끊기거나 비싸다. 그래서 운영체제 설정과 별개로 앱 안에서도 켤 수 있다.
  - **설정:** `createTheme({ reduceMotion: true, reduceTransparency: true })`
  - `reduceMotion`:
    - `true`: 항상 줄인다.
    - `false`: 줄이지 않는다.
    - `'system'`(기본): 운영체제 설정을 따른다.
  - **동작 줄이기가 켜지면:** 모든 상태 변화가 즉시 끝난다(CSS 전환은 0초, 스프링은 즉시 이동, 피어남은 짧은 페이드). 포인터를 따라다니는 빛도 꺼진다. 스피너와 진행 표시는 의미가 있는 움직임이라 천천히 계속 움직인다. 스피너는 1.4초에 한 바퀴, 진행 표시는 이동 대신 옅게 깜빡인다.
  - **투명도 줄이기가 켜지면:** 블러를 쓰지 않는 불투명 표면이 되어 스트리밍 대역과 GPU 부담이 줄어든다.
  - **검사:** `tests/e2e/reduce-motion.mjs`가 앱 안 설정과 시스템 설정 두 경로를 모두 검사한다.

## 5. 모션 목록 — 상태가 바뀌는 모든 순간

규칙: 상태가 바뀌는 곳은 하나도 빠짐없이 움직이고, 순간이동하지 않는다. 다만 손가락을 1:1로 따라가는 동안에만 스프링을 끈다.

| 컴포넌트 | 바뀌는 순간 | 모션 |
|---|---|---|
| 버튼 | 누름 / 로딩 | 0.965배로 들어감(snappy) / 라벨이 사라지며 스피너가 0.6배에서 나타남 |
| 스위치 | 켜기·끄기, 누름, 끌기 | 물방울(앞쪽 snappy·뒤쪽 smooth), 누르면 6px 뻗음, 끌 때는 손가락을 1:1로 따라감 |
| 슬라이더 | 트랙 누름, 끌기, 키보드 | 누른 곳까지 snappy로 이동하고 손잡이 1.18배와 말풍선이 함께 이동. 3px 넘게 움직이면 1:1로 따라감 |
| 스테퍼 | 값 변경 | 숫자가 바뀐 방향(올림 ↑, 내림 ↓)에서 굴러 들어옴(snappy) |
| 세그먼트·탭 바 | 선택 | 물방울 다리(앞쪽 snappy, 뒤쪽 smooth). 끄는 동안은 바 안에서 손가락을 따라감 |
| 탭 바 뱃지·뱃지 | 나타남 / 숫자 변경 | 0.4배에서 튀어나옴 / 1.28배로 한 번 튐(bouncy) |
| 페이지 컨트롤 | 페이지 | 현재 점이 늘어나고 이전 점이 줄어듦(snappy) |
| 텍스트 필드 | 포커스 / 지우기 버튼 | 테두리와 바깥 링이 번짐 / 0.4배에서 튀어나옴 |
| 검색 필드 | 취소 버튼 | 오른쪽에서 밀려 들어오며 필드가 부드럽게 좁아짐(smooth) |
| 진행 막대 | 값 | 채움이 smooth로 늘어남 |
| 앱 바 | 맨 위 ↔ 스크롤 | 투명에서 유리로 페이드(배경·그림자·블러·테두리 320ms) |
| 메뉴·팝오버 | 열기 / 닫기 | 앵커 반대쪽으로 펼쳐짐(pop) / 앵커 쪽으로 150ms에 접힘 |
| 대화상자 | 열기 / 닫기 | 0.9배에서 피어남(bouncy) / 0.96배로 줄며 사라짐 |
| 시트·액션 시트 | 열기 / 닫기 / 끌기 | 아래에서 올라옴(gentle·smooth) / 내려감 / 손가락을 따라가고 짧게 끌면 제자리로(smooth) |
| 컨텍스트 메뉴 | 열기 | 항목이 1.03배로 떠오르고 메뉴가 피어남 |
| 토스트 | 나타남 / 사라짐 / 쌓임 변화 | 위에서 내려오며 튐(bouncy) / 위로 사라짐 / 남은 토스트가 빈자리로 미끄러짐(smooth) |
| 유리 하이라이트 | 포인터 이동 | 합성 레이어 transform, 멀어지면 260ms에 흐려짐 |

## 6. 모션 성격 (personality)

다섯 스프링(snappy · smooth · bouncy · gentle · pop)은 그대로 두고, 그 성격만 세 가지 중에서 고른다. 기본값은 **lively**다.

| 성격 | 성격 설명 | snappy 넘침 | smooth 넘침 | pop 넘침 | 납작해짐(squash) | 젤리 늘어남(gel) / 따라오는 지연(lag) | 어울리는 곳 |
|---|---|---|---|---|---|---|---|
| calm | 넘침 없이 정확하게 멈춤 | 0.5% | 0 | 7% | 0 | 0 / 0 | 업무용, 정보가 많은 화면 |
| **lively** | 한 번 살짝 넘쳤다 자리 잡음 | 4.6% | 3.8% | 10.7% | 0.14 | 0.14 / 90ms | 대부분의 앱 |
| playful | 탄성이 큼 | 9.5% | 5.4% | 13.3% | 0.22 | 0.20 / 120ms | 소비자 앱, 온보딩 |

**정하는 방법:** 아래 세 가지 중 하나로 정한다.
- 앱 전체: `createTheme({ motion })`
- 일부 영역: `<MotionScope motion>`
- 컴포넌트 하나: 컴포넌트의 `motion` 속성

**적용 범위:**
- **CSS:** `[data-gl-motion]`에 성격별 `--gl-spring-*` 값이 들어 있다.
- **JS:** 탭·세그먼트 표시와 슬라이더 손잡이는 가장 가까운 `[data-gl-motion]`에서 성격을 읽는다.
- **포털:** 메뉴·팝오버·시트·대화상자는 포털로 뜨지만 같은 성격을 이어받는다.

**성격이 바꾸는 효과:**
- **세그먼트·탭 표시:** 늘어나는 만큼 위아래로 납작해졌다가, 모일 때 둥글게 돌아온다. 최소 높이 비율은 calm 1.0, lively 0.90, playful 0.85다. 표시는 트랙의 첫 칸과 마지막 칸 바깥으로 절대 나가지 않는다. 끝에서 넘치려는 힘은 벽에 눌려 폭이 좁아지는 것으로 바뀐다.
- **슬라이더 손잡이:**
  - 트랙을 누르면 snappy 스프링으로 이동한다.
  - 끌면 손가락을 lag만큼 늦게 따라오고, 속도에 따라 가로로 늘어나고 세로로 줄어든다. 빠르게 끌 때 calm 1.0, lively 1.22, playful 1.38배까지 늘어난다.
  - 놓으면 1.0으로 돌아온다.
- **스위치:** 이동 거리(20px)가 짧아서 스프링이 넘치는 양만으로는 성격 차이가 거의 보이지 않는다. 그래서 손잡이(knob)가 끝에 닿는 순간 벽 쪽으로 눌렸다가 둥글게 돌아오게 했다. 가장 많이 눌렸을 때의 폭은 calm 1.0, lively 0.85, playful 0.77배다.
- **스테퍼:** 숫자가 계기판처럼 굴러간다. 이전 숫자는 반대쪽으로 빠져나가고, 새 숫자가 snappy 스프링으로 들어온다. 위아래 가장자리는 흐리게 처리한다.
- **나머지:** 진행 막대와 페이지 점은 CSS 스프링을 그대로 따른다.
- **동작 줄이기:** 시스템의 동작 줄이기가 켜져 있으면 성격과 상관없이 모든 움직임이 즉시 끝난다.

## 7. 속도를 일정하게 느끼게 하는 규칙

같은 성격 안에서도 컴포넌트마다 빠르기가 다르게 느껴질 수 있다. 원인은 두 가지였고, 각각 규칙으로 막는다.

1. **목표가 바뀌는 움직임은 JS 스프링으로 만든다.**
   - **원인:** CSS 전환은 목표가 바뀔 때마다 속도 0에서 다시 출발한다. 스위치는 탭 한 번에 목표가 세 번 바뀌었다(누름 → 전환 → 눌림 해제). 진행 막대는 값이 들어올 때마다 바뀐다.
   - **결과:** JS 스프링은 목표가 바뀌어도 속도를 이어간다. 진행 막대에 값이 연이어 들어올 때, CSS는 속도가 38%까지 떨어졌다가 다시 가속했다. JS 스프링은 105~118%를 유지했다(`tests/e2e/progress-tick.mjs`).
   - **해당 컴포넌트:** 스위치, 슬라이더, 세그먼트·탭 표시, 진행 막대.
2. **짧게 움직이는 것은 같은 성격의 더 빠른 스프링을 쓴다.**
   - **원인:** 스위치 손잡이는 약 20px, 세그먼트 표시는 약 90px을 움직인다. 같은 스프링이면 스위치가 4분의 1 거리를 같은 시간에 가서 굼떠 보인다.
   - **적용:** 스위치는 성격의 snappy 스프링을 앞쪽 끝 0.62배, 뒤쪽 끝 0.82배 응답 시간으로 쓴다(넘침 비율은 같다). 탭하는 순간 초기 속도도 준다. 손잡이가 끝에 닿는 순간을 감지해 그때 눌림 효과를 낸다.
   - **결과(lively):** 클릭 후 앞쪽 끝 도착이 153ms에서 약 90ms로, 손잡이 전체 정착이 237ms에서 약 150ms로 줄었다. 세그먼트는 90px 이동의 90% 지점까지 약 190ms다.
