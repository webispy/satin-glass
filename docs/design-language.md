# Satin Glass 디자인 언어

> 디자인 언어에서 실제로 정한 값과 그 이유를 정리한다. 모든 결정은 0장의 원칙으로 설명할 수 있어야 한다.

## 0. 원칙

| 원칙 | 뜻 | 이것으로 정해지는 것 |
|---|---|---|
| **새틴 유리** | 빛을 굴절시키는 맑은 유리가 아니라, 빛을 고르게 흩뜨리는 결 있는 반투명. 뒤가 부드럽게 비치되 렌즈처럼 휘지 않는다 | 블러 + 미세한 결, 굴절·렌즈 효과 없음, 점 반사광 대신 번지는 광택 |
| **두 개의 빛** | 위에서 오는 고정된 빛이 형태를, 손끝을 따르는 새틴 광택이 생기를 준다 | 밝은 윗변·그늘진 아랫변·홈과 볼록(8장)은 고정, 포인터 광택만 움직임 |
| **표면장력** | 선택은 가는 쪽으로 늘어났다가 도착하면 달라붙는다. 제 레일을 떠나지 않고, 차분할수록 점성이 높다 | 물방울 다리(탭 바·세그먼트·스위치), 성격별 squash·gel(6장) |
| **손끝의 감촉** | 눌리는 것은 들어가고 손가락 아래로 빛이 모인다. 잡는 것·고른 것은 볼록, 그것이 움직이는 길은 홈 | 눌림 0.965배, 깊이 토큰(8장) |
| **작고 드문 기쁨** | 한 번의 조작에 눈에 띄는 움직임은 하나. 반복하는 조작에는 효과를 얹지 않는다 | 반복 조작 중에는 손에 답하는 움직임만: 휠 렌즈는 줄이 끄는 쪽으로 오므라들었다가 줄이 멈출 때 한 번 튀어나와 제자리로. 장식 효과(빛 스침, 색 바뀜)는 없음 |
| **누구에게나 매끄럽게** | 고대비는 윤곽선, 투명도 줄이기는 불투명 판, 동작 줄이기는 짧고 넘치지 않는 움직임. 포커스는 언제나 보이고 60fps를 지킨다 | 4장 접근성, 3장 성능 규칙, e2e `focus`·`settings`·`perf` |

두 원칙이 부딪히면 위에 있는 것을 따른다. 단 마지막 원칙은 언제나 지켜야 하는 바닥이다.

## 1. 주요 결정

| 영역 | 결정 | 이유 |
|---|---|---|
| 재질 | **새틴 유리**: 블러 + 채움 위의 미세한 결(`--sg-glass-grain`, 고대비에서는 없음) + 빛 쪽만 밝은 그라디언트 테두리 + 안쪽 깊이 그라디언트 + 포인터를 따르는 **새틴 광택**(점이나 띠가 아니라 유리 위로 넓고 옅게 번지는 빛 — 반짝이지 않고 은은하게) + 배경색이 스며드는 틴트(선택). 굴절·렌즈 효과는 쓰지 않는다 | 이름 그대로의 재질(빛을 흩뜨리는 산 부식 유리), 모든 브라우저에서 같은 모습, 요소별 이미지 불필요. 결은 정적인 배경이라 성능 비용이 없다(CPU 4배 감속에서 프레임 드롭 0) |
| 모양 | **고정 반경**: 컨트롤 12 · 카드 16 · 바/패널 22 · 시트 28. 캡슐은 칩, 토글, 배지만 | 정보 밀도, 크기마다 일정한 모서리 |
| 바 | 화면 끝에서 12px 띄운 떠 있는 바, 반경 22 | 바와 내용이 겹쳐도 화면 끝과 구분됨 |
| 색 | **OKLCH 자체 팔레트** 11색 × 11단계. 강조색 iris(보라 쪽 파랑) | 대비를 예측할 수 있는 단계 |
| 글꼴 | **Pretendard** → 시스템. 본문 16px | 재배포 가능, 한글 품질 |
| 아이콘 | 라이브러리는 자체로 그린 최소 글리프만 포함. 앱은 Lucide 등을 쓴다 | 라이브러리를 가볍게. 아이콘 세트는 앱이 고른다 |
| 탭 선택 | **물방울 다리**: 선택 표시가 바 안에서 앞쪽 끝이 먼저 늘어나 다음 탭까지 이어졌다가 모임. 끌면 바 안에서 손가락을 따라감 | 세그먼트 컨트롤·스위치와 같은 물방울 언어 |
| 팝업 등장 | **피어남(bloom)**: 앵커에 가장 가까운 점에서 앵커 반대쪽으로 펼쳐짐(메뉴는 가로 0.6 · 세로 0.3배에서 시작). `pop` 스프링으로 ~110ms 만에 90 %, 한 번 넘쳤다 자리 잡음. 닫힐 때는 150ms 만에 앵커 쪽으로 접혀 사라짐. transform·opacity만 사용 | 합성기에서만 실행, 빠른 체감 |
| 눌림 | 살짝 들어감(0.965배) + 손가락 아래로 빛이 모임 | 물리적인 감각 |
| 스위치 | 탭 바와 같은 물방울: 양 끝이 각자 스프링으로 움직여(둘 다 성격의 snappy에서 파생, 앞쪽이 더 빠름 — 7장) 가는 쪽으로 늘어났다 모임. 켤 때·끌 때 똑같고 레일을 벗어나지 않음. 누르면 갈 쪽으로 6px 뻗음. 끌다가 위아래 48px·좌우 120px 넘게 벗어나면 놓아 줌 | 일관성, 오조작 방지 |
| 모션 | **이름 붙은 스프링 5개**(snappy · smooth · bouncy · gentle · pop). CSS는 `linear()` 이징, 손가락 동작은 같은 값의 JS 스프링. 값은 6장의 생성된 표 | 일관성, 성능 |
| 컨텍스트 메뉴 배경 | 어둡게만 하고 항목은 1.03배로 떠오름 | 성능 |
| 스크롤 가장자리 | 색 그라디언트만 | 성능 |

## 2. 토큰

- **색**: `--sg-<hue>-<step>`(원시) + `--sg-<semantic>`(테마별). 빌드할 때 대비를 검사하고, 기준에 못 미치면 빌드가 실패한다.
  - 기본 테마: 본문 7:1, 보조 텍스트 4.5:1, 강조 텍스트 4.5:1
  - 고대비 테마: 기준을 한 단계씩 올림(본문·보조·강조 텍스트 모두 7:1)
- **재질**: `--sg-glass-fill(-strong|-subtle|-clear)`, `--sg-glass-rim-lit/-shade`, `--sg-glass-depth`, `--sg-glass-highlight`, `--sg-blur(-strong|-subtle)`
  - **팔레트의 단계는 밝기 순서다:** 같은 단계(예: 500)는 같은 OKLCH 밝기에서 출발하지만, 최종 sRGB 색의 WCAG 대비는 색마다 다르다(500의 흰 글자 대비가 jade 3.1 : 1, ruby 3.7 : 1). 글자와 상태 표시에는 단계 번호가 아니라 검사를 통과한 의미 색을 쓴다. 문서의 색 페이지가 칸마다 흰·검은 글자 대비를 보여 준다.
- **재질**: `--sg-glass-fill(-strong|-subtle|-clear)`, `--sg-glass-rim-lit/-shade`, `--sg-glass-depth`, `--sg-glass-highlight`, `--sg-blur(-strong|-subtle)`
- **간격**: `--sg-space-<n>`(0 · 0.5 · 1 · 1.5 · 2 · 2.5 · 3 · 4 · 5 · 6 · 8 · 10 · 12 · 16 = 4px 단위). `Stack`의 `gap={3}`처럼 단계 숫자를 쓰면 그 토큰을 읽으므로 테마에서 간격 토큰을 바꾸면 따라온다(단계에 없는 숫자는 4px 배수).
- **글자**: 본문·제목은 `Text`의 변형(`--sg-text-<variant>-size/-line/-weight/-tracking`). 컨트롤은 글자 역할을 따로 갖는다 — 테마가 바꾸면 모든 컨트롤이 따라온다.

| 역할 | 크기 / 줄 / 굵기 | 쓰는 곳 |
|---|---|---|
| `control-lg` | 16 / 22 / 620 | 큰 버튼 |
| `control` | 15 / 20 / 620 | 버튼 |
| `control-sm` | 14 / 18 / 560 | 작은 버튼, 세그먼트, 칩 |
| `label` | 13 / 18 / 620 | 입력란 위 라벨 |
| `item` | 15 / 20 / 450 | 메뉴·셀렉트 목록의 항목 |

  도움말은 `caption`을 쓴다.
- **모션**: `--sg-spring-<name>`(linear 이징) + `--sg-spring-<name>-duration`. 성격별 실제 값(90% 도달·넘침·정착)은 6장의 생성된 표에 있다.

| 스프링 | 쓰임 |
|---|---|
| snappy | 탭, 토글, 눌림, 짧은 이동 |
| smooth | 선택 이동, 제자리 복귀, 내비게이션 스택의 화면 넣기·빼기(앞뒤로 자주 오가므로 빠른 쪽) |
| bouncy | 대화상자, 토스트, 뱃지 |
| gentle | 시트, 드로어 |
| pop | 메뉴·팝오버·셀렉트 피어남, 고른 칸이 차오름 |

## 3. 성능 규칙

1. **움직이는 속성:** 세 등급으로 나눈다. 검사는 `packages/core/test/css-rules.test.ts`(`pnpm test`)가 모든 스타일시트에서 한다.
   - **자유:** `transform` · `translate` · `scale` · `rotate` · `opacity`. 합성기에서만 움직인다.
   - **칠하기만:** 색·배경·테두리 색·그림자(`box-shadow`)·SVG 칠. 레이아웃은 건드리지 않고 다시 칠하기만 한다. 짧은 상태 전환에만 쓴다(매 프레임 바꾸지 않는다).
   - **그 밖(레이아웃·필터):** **허용 목록 한 곳**(`packages/core/test/css-allowlist.json`)에 요소·속성·이유가 적힌 것만 된다. 지금은 검색 취소 버튼(필드가 좁아짐), 페이지 점의 폭, 앱 바가 유리로 바뀌는 순간의 배경 필터다. 목록에 없는 새 전환은 검사가 실패하고, 더 이상 쓰이지 않는 항목도 실패한다.
   - **JS가 매 프레임 쓰는 레이아웃 값:** 탭·세그먼트 표시기의 `width`(`contain: layout` 안), 스위치 손잡이의 양 끝, 기간 띠의 폭. 모두 작은 요소 하나이고 배경 필터가 없다.
   - **값도 토큰에서:** 반경은 반경 토큰(또는 부모의 `--_radius`), 그림자는 그림자·깊이 토큰, 시간은 시간·스프링 토큰에서 온다. 날 값은 윤곽선(고대비·포커스의 `inset 0 0 0 Npx`), 전환용 투명 그림자, 끝없이 도는 반복(스피너·스켈레톤 — 반응이 아니라 박자)에만 쓴다. 같은 검사가 확인한다.
2. **블러 예산:** 비용은 블러가 덮는 면적과 겹침에서 나온다. 그래서 세 가지로 잰다(e2e `blur-budget`, 모든 문서 페이지를 데스크톱·휴대폰 폭에서, 쇼케이스를 스크롤한 상태와 메뉴·대화상자를 연 상태까지).
   - **한 층에 하나:** 블러하는 유리 안에 블러하는 유리를 두지 않는다. 유리 안의 유리(유리 바의 유리 버튼, 유리 패널의 유리 컨트롤)는 부모의 유리를 함께 쓰며 평평하게 그려진다(자동, `foundation.css`). 예외: 아직 유리가 아닌 부모(맨 위에서 투명한 앱 바), 잠깐 떠오르는 것(슬라이더 값 말풍선).
   - **겹침은 3까지:** 화면의 어느 점에서도 블러가 3겹을 넘지 않는다(바, 패널 하나, 시트 하나).
   - **큰 유리는 6개까지:** 한 변이 120px을 넘는 블러 표면(바·패널·시트·카드)은 한 화면에 6개까지다. CPU 4배 감속에서 유리 카드 다섯 장과 사이드바가 프레임을 떨어뜨리지 않은 측정(`perf`)이 근거다. 작은 유리(버튼·칩·페이지 점)는 겹치지 않는 한 개수 제한이 없다.
   - 전체 화면 블러는 쓰지 않는다.
3. **포인터 빛:** 포인터 이벤트는 창 하나에서만 받고 rAF로 묶는다. 요소 위치는 스크롤·크기 변화가 있을 때만 다시 잰다. 하이라이트는 합성 레이어의 transform으로만 움직인다.
4. **제스처 상태:** 끌기·눌림 상태는 React 상태나 data 속성에 둔다. 클래스에 두면 다시 그릴 때 지워진다.
5. **유리 표면은 스스로 스크롤하지 않는다.**
   - **규칙:** 유리는 항상 바깥에서 잘라내고(`overflow: hidden`), 스크롤은 안쪽 요소가 맡는다. 사이드바는 `.sg-sidebar__scroll`, 대화상자는 `.sg-dialog__scroll`, 메뉴는 `[data-sg-content]`가 스크롤한다.
   - **이유:** 포인터 하이라이트는 유리 안에 절대 위치로 놓인 요소다. 유리가 스스로 스크롤하면, 하이라이트가 가장자리로 갈 때 스크롤 영역이 커져서 스크롤바가 생긴다.
   - **검사:** e2e가 모든 문서 페이지에서 스크롤하는 유리 표면이 없는지 확인한다.
6. **앵커형 패널은 페이지에 붙는다.**
   - **규칙:** 메뉴·팝오버·셀렉트 목록·날짜 패널은 문서 좌표(`position: absolute`)에 놓는다. 페이지 스크롤은 브라우저가 패널을 앵커와 함께 옮기므로 JS가 하는 일이 없고 지연도 없다. 안쪽 스크롤 영역(사이드바, 대화상자 본문 등)만 스크롤 이벤트 안에서 앵커가 움직인 만큼 옮긴다.
   - **스크롤 영역이 자르면 패널도 잘린다:** 앵커가 안쪽 스크롤 영역(휴대폰 화면, 대화상자 본문)에 있으면, 패널은 그 영역 안의 내용처럼 영역의 가장자리 밑으로 들어가 잘리고, 다 가려지면 숨는다(보이지 않는 클릭도 받지 않음). 앵커가 돌아오면 그대로 다시 보인다. 처음 열릴 때부터 영역 밖으로 펼쳐진 쪽(사이드바 밖으로 열리는 목록)은 자르지 않는다. 둥근 모서리만 자르는 카드는 스크롤 영역으로 보지 않는다. 검사: e2e `edge`.
   - **스크롤로 닫지 않는다:** 패널은 피어나온 앵커의 일부처럼 행동한다. 앵커와 함께 화면 밖으로 나갔다 돌아와도 그대로 있고, 닫는 방법은 Esc·바깥 클릭·항목 선택이다. 스크롤 중에는 뒤집기·가장자리 맞춤을 하지 않아 튀지 않고, 창 크기가 바뀔 때만 열린 쪽 그대로 다시 놓는다.
   - **예외:** 컨텍스트 메뉴는 항목을 들어 올리고 배경을 어둡게 하는 집중 상태라 열려 있는 동안 페이지 스크롤을 막는다.
   - **검사:** e2e가 3개 엔진에서 휠 스크롤 중 모든 프레임의 패널–앵커 간격을 재서 차이가 0인지 확인한다.
7. **마운트할 때 레이아웃을 강제로 읽지 않는다 (0.3).**
   - **규칙:** 차트 폭과 표의 고정 머리글 위치는 `ResizeObserver`로 받는다. 즉, 브라우저가 레이아웃을 마친 뒤에 받는다. 레이아웃 효과 안에서 `clientWidth`나 `offsetTop`을 읽지 않는다. 대시보드처럼 많은 것이 한꺼번에 붙을 때, 그런 읽기 하나가 새 화면 전체의 레이아웃을 그 자리에서 강제한다.
   - **보조 규칙:** 탭 패널 내용은 지연 렌더링(`useDeferredValue`)으로 잘게 나눠 그린다. 물방울 선택 표시는 이동을 시작할 때 한 번만 잰다. 차트는 폭을 알기 전 한 프레임 동안 같은 높이의 빈 상자로 자리를 지킨다.
   - **예외:** 같은 내용을 페이지에서 처음 배치할 때는 글자 조판 등 일회성 비용이 든다(대시보드 탭 첫 전환은 CPU 4배 감속에서 약 116ms). 두 번째부터는 프레임 드롭이 없다.
8. **높이가 바뀌는 애니메이션 (0.3).**
   - 아코디언 영역이 펼쳐지고 접힐 때와 배너가 닫힐 때의 높이(둘 다 JS 스프링)다. 짧게 한 요소만 바뀌고, 아래 내용이 자리를 내줘야 해서 허용한다. 아코디언은 성격의 smooth 스프링을 그대로 써서(CSS의 fr 단위는 1을 넘지 못해 넘침이 잘렸다) 성격마다 다르게 펼쳐진다.
   - 동작 줄이기에서는 둘 다 바로 바뀐다.
   - 차트 데이터가 바뀔 때의 선 모양 전환은 작은 SVG의 경로를 다시 그린다(420ms, 블러 없음). 동작 줄이기에서는 바로 바뀐다.
9. **제스처 처리:** 끌기는 시작부터 끝까지 창 단위로 듣는다. 그래서 포인터가 어디서 떨어지든 제스처가 반쯤 끝난 채로 남지 않는다. 문턱(threshold)이 있는 끌기는 실제로 끌기가 시작될 때 포인터를 붙잡는다. 누르는 순간 붙잡으면 시트 머리의 취소·완료 같은 안쪽 버튼의 클릭이 사라지기 때문이다.

측정 결과는 Chromium, CPU 4배 감속 기준이다(`tests/e2e/perf.mjs`).
- **통과:** 탭 이동, 메뉴, 대화상자, 시트, 토스트, 스위치, 세그먼트, 포인터 빛, 유리 바 아래 스크롤에서 프레임 드롭 없음
- **알려진 예외:** 페이지에서 처음 하는 동작은 코드와 스타일 준비 비용 때문에 첫 프레임이 1번 늦을 수 있다. 시트 첫 열기는 약 70ms였고, 두 번째부터는 약 8ms다.

## 4. 접근성

- **키보드:** 모든 컴포넌트를 키보드로 조작할 수 있다. 탭·세그먼트는 방향키로 이동하고, 메뉴는 방향키·Home/End·첫 글자 찾기를 지원한다. 오버레이는 Esc로 닫는다. 대화상자와 시트는 포커스를 가두고, 닫히면 포커스를 원래 자리로 돌려준다.
- **Safari 대응:** Safari는 Tab으로 버튼을 건너뛰는 게 기본 설정이라, 포커스 가두기가 Tab 이동을 직접 처리한다. 버튼 클릭으로 포커스가 가지 않는 Safari 동작 때문에, 메뉴는 닫힐 때 포커스를 앵커로 돌려준다.
- **시스템 설정:** 시스템의 동작 줄이기, 투명도 줄이기, 고대비, 강제 색상 모드를 따른다. `createTheme`으로 직접 지정할 수도 있다.
- **앱 안에서 줄이기:** VDI·원격 데스크톱처럼 화면을 스트리밍하는 환경에서는 애니메이션과 블러가 끊기거나 비싸다. 그래서 운영체제 설정과 별개로 앱 안에서도 켤 수 있다.
  - **설정:** `createTheme({ reduceMotion: true, reduceTransparency: true })`
  - `reduceMotion`:
    - `true`: 항상 줄인다.
    - `false`: 줄이지 않는다.
    - `'system'`(기본): 운영체제 설정을 따른다.
  - **동작 줄이기가 켜지면:** "모두 즉시"로 바꾸지 않는다. 스위치처럼 탭 한 번에 상태가 여러 번 바뀌는 컨트롤은, 즉시 바꾸면 2~3프레임에 툭툭 끊겨 바뀌면서 오히려 버벅여 보인다. 그래서 움직임을 크기별로 나눠 처리한다.
    - **작은 상태 변화** (스위치, 선택 표시, 슬라이더, 진행 막대, 페이지 점): 넘치지 않는 짧은 스프링(`reducedMotion`, 응답 0.18초, 감쇠 1)으로 한 방향으로 미끄러진다. 90% 지점까지 약 110ms 걸린다.
    - **꺼지는 효과:** 늘어남·납작해짐·젤리·뒤따라옴, 누를 때 넓어짐·들어감, 포인터 빛.
    - **큰 움직임** (시트·액션 시트가 올라옴, 메뉴·대화상자가 피어남, 토스트 미끄러짐, 컨텍스트 메뉴 떠오름, 뱃지 튀어나옴): 제자리에서 짧게 페이드된다(약 140ms 나타남, 110ms 사라짐).
    - **내용 변화** (스테퍼 숫자, 뱃지 숫자): 숫자가 바뀌는 건 움직임이 아니라 내용 변화라서 그냥 바뀐다. 굴림도 교차 페이드도 쓰지 않는다. 같은 자리에서 두 숫자가 겹쳐 페이드되면 흐릿하게 보이기 때문이다.
    - **누름 효과:** 버튼·칩·카드·탭 아이콘·유리 표면이 들어가는 효과와 슬라이더 손잡이가 커지는 효과는 모두 없다.
    - **계속 움직이는 표시:** 스피너는 1.4초에 한 바퀴 돈다. 미확정 진행 표시는 이동하지 않고 옅게 깜빡인다. 스켈레톤도 빛이 지나가지 않고 2초 주기로 숨 쉬듯 밝아졌다 어두워진다.
    - **큰 동작 (0.2):** 미디어 뷰어는 썸네일에서 커지지 않고 제자리에서 페이드로 열리고 닫힌다. 버튼·키로 넘길 때도 미끄러지지 않고 바뀐다. 손가락으로 끌 때는 손가락을 따라가고, 놓으면 넘침 없이 자리 잡는다. 큰 제목의 작은 제목은 떠오르지 않고 페이드만 한다.
  - **투명도 줄이기가 켜지면:** 블러를 쓰지 않는 불투명 표면이 되어 스트리밍 대역과 GPU 부담이 줄어든다.
  - **검사:** `tests/e2e/reduce-motion.mjs`가 앱 안 설정과 시스템 설정 두 경로를 모두 검사한다. 확인 항목은 한 방향 이동, 넘침 없음, 늘어남 없음, 페이드로 대체, 빛 꺼짐이다. 여기에 컴포넌트 29곳에서 확대·이동이 없는지도 확인한다(0.2: 셀렉트, 체크, 라디오, 달 전환, 미디어 뷰어 열기·넘기기, 스켈레톤). `SANITY=1`로 실행하면 동작을 줄이지 않은 상태에서 같은 검사가 모두 실패하는지 확인할 수 있다. 검사가 움직임을 실제로 감지한다는 증거다.

## 5. 모션 목록 — 상태가 바뀌는 모든 순간

규칙: 상태가 바뀌는 곳은 하나도 빠짐없이 움직이고, 순간이동하지 않는다. 다만 손가락을 1:1로 따라가는 동안에만 스프링을 끈다.

들어오고 움직이는 것은 성격의 스프링을 탄다. **나가는 것은 스프링을 타지 않는다:** 짧은 ease-in으로 떠나고 튀지 않는다(시트 내려감, 액션 시트, 토스트, 앵커로 접힘, 미디어 뷰어가 썸네일로 돌아감). 그 시간과 곡선, 동작 줄이기의 대체 페이드(나타남 140ms, 사라짐 110ms)는 core의 이름 붙은 값(`timing`, `easing`) 한곳에서 가져온다. 의도적으로 성격과 무관하게 고정한 것: 휠 렌즈가 끌려 들어가는 힘(실제로 지나가는 줄에 반응하는 빠르고 단단한 당김; 깊이와 되튐은 성격을 따름).

| 컴포넌트 | 바뀌는 순간 | 모션 |
|---|---|---|
| 버튼 | 누름 / 로딩 | 0.965배로 들어감(snappy) / 라벨이 사라지며 스피너가 0.6배에서 나타남 |
| 스위치 | 켜기·끄기, 누름, 끌기 | 물방울(앞·뒤 끝 모두 snappy 파생, 앞쪽이 빠름), 누르면 6px 뻗음, 끌 때는 손가락을 1:1로 따라감 |
| 슬라이더 | 트랙 누름, 끌기, 키보드 | 누른 곳까지 snappy로 이동하고 손잡이 1.18배와 말풍선이 함께 이동. 3px 넘게 움직이면 손가락을 따라감(calm은 1:1, lively·playful은 성격의 lag만큼 늦게) |

| 탭 (0.3) | 선택 / 패널 | 밑줄이 물방울 다리로 이동(탭 바와 같음) / 새 패널이 이동한 쪽에서 12px 미끄러지며 나타남(snappy) |
| 차트 (0.3) | 처음 / 데이터 변경 / 계열 숨김 | 선이 그려지고 막대가 바닥에서 차례로 올라오며 도넛이 돌며 펼쳐짐 / 이전 값에서 이어짐(420ms) / 축이 새 범위로 함께 이어짐 |
| 표 (0.3) | 정렬 / 불러오는 중 | 정렬 화살표가 방향을 바꿈 / 행이 흐려지고 머리글 아래로 진행선이 지나감 |
| 아코디언 (0.3, 0.5에서 고침) | 열기 / 닫기 | 메뉴의 피어남을 구역에 옮긴 것: 영역의 높이와 화살표는 smooth 스프링으로, 내용은 제목 줄 뒤(28px 위, squash만큼 작게)에서 pop 스프링으로 나와 출렁이며 자리 잡음(차분은 넘침 없음). 닫을 때는 제목 줄 뒤로 접혀 들어가고, 영역이 닫히는 순간 멈춤. 동작 줄이기: 높이는 바로, 내용만 짧게 나타남 |
| 배너 (0.3) | 닫기 | 흐려진 뒤 높이가 접힘(작아지지 않음) |
| 타임라인 (0.5) | 지금 단계가 바뀜 | 위치 점이 선을 따라 smooth 스프링으로 이동(가는 쪽으로 늘어남, squash 비례), 지나는 선이 점까지 강조색으로 채워지고 지나친 단계는 체크가 그려짐. 목적지를 지나치지 않고 넘치는 힘은 그 자리에서 눌림으로 받으며, 점이 닿는 순간 링이 안쪽으로 밀렸다가 pop 스프링으로 되튐(크기를 순간적으로 바꾸지 않음). 기록 항목이 추가되면 줄이 smooth 스프링으로 펼쳐지고 표시가 pop으로 붙고, 빠지면 접힌 뒤 사라짐. 동작 줄이기: 제자리에서 바뀜 |
| 지표(Stat) (0.3) | 값 변경 | 새 값이 6px 아래에서 올라오며 나타남(snappy). 동작 줄이기에서는 바로 바뀜 |
| 토스트 | 나타남 / 사라짐 / 쌓임 변화 | 위에서 내려오며 튐(bouncy) / 위로 사라짐 / 남은 토스트가 빈자리로 미끄러짐(smooth) |
| 유리 하이라이트 | 포인터 이동 | 합성 레이어 transform, 멀어지면 260ms에 흐려짐 |

## 6. 모션 성격 (personality)

다섯 스프링(snappy · smooth · bouncy · gentle · pop)은 그대로 두고, 그 성격만 세 가지 중에서 고른다. 기본값은 **lively**다.

| 성격 | 성격 설명 | 어울리는 곳 |
|---|---|---|
| calm | 눈에 띄는 넘침 없이 멈춤(모든 스프링 0.5% 이하), 늘어남·납작해짐 없음 | 업무용, 정보가 많은 화면 |
| **lively** | 한 번 살짝 넘쳤다 자리 잡음 | 대부분의 앱 |
| playful | 탄성이 큼, 더 늘어나고 더 납작해짐 | 소비자 앱, 온보딩 |

**정하는 방법:** 아래 두 가지로 정한다.
- 앱 전체: `createTheme({ motion })`
- 일부 영역이나 컴포넌트 하나: `<MotionScope motion>`으로 감싼다. 컴포넌트에는 `motion` 속성이 없다(성격은 테마 수준의 설정이고, 움직임을 더할 때마다 공개 API가 늘지 않게). 감싸는 요소는 `display: contents`라 상자를 만들지 않지만 DOM 부모는 되므로, 버튼 그룹·탭 바처럼 자식 관계로 모양을 정하는 묶음은 묶음 전체를 감싼다.

**적용 범위:**
- **CSS:** `[data-sg-motion]`에 성격별 `--sg-spring-*` 값이 들어 있다.
- **JS:** 탭·세그먼트 표시와 슬라이더 손잡이는 가장 가까운 `[data-sg-motion]`에서 성격을 읽는다.
- **포털:** 메뉴·팝오버·시트·대화상자는 포털로 뜨지만 같은 성격을 이어받는다.

**성격이 바꾸는 효과:**
- **세그먼트·탭 표시:** 늘어나는 만큼 위아래로 납작해졌다가, 모일 때 둥글게 돌아온다(최소 높이는 위 표). 표시는 트랙의 첫 칸과 마지막 칸 바깥으로 절대 나가지 않는다. 끝에서 넘치려는 힘은 벽에 눌려 폭이 좁아지는 것으로 바뀐다.
- **슬라이더 손잡이:**
  - 트랙을 누르면 snappy 스프링으로 이동한다.
  - 끌면 손가락을 lag만큼 늦게 따라오고, 속도에 따라 가로로 늘어나고 세로로 줄어든다(최대 폭은 위 표).
  - 놓으면 1.0으로 돌아온다.
- **스위치:** 이동 거리(20px)가 짧아서 스프링이 넘치는 양만으로는 성격 차이가 거의 보이지 않는다. 그래서 손잡이(knob)가 끝에 닿는 순간 벽 쪽으로 눌렸다가 둥글게 돌아오게 했다(최소 폭은 위 표).
- **스테퍼:** 숫자가 계기판처럼 굴러간다. 이전 숫자는 반대쪽으로 빠져나가고, 새 숫자가 snappy 스프링으로 들어온다. 위아래 가장자리는 흐리게 처리한다.
- **나머지:** 진행 막대는 JS 스프링(7장), 페이지 점은 CSS 스프링을 따른다.
- **동작 줄이기:** 성격과 상관없이 위 표의 '동작 줄이기' 열(넘침 없이 ~110ms에 90%)로 바뀌고, 늘어남·납작해짐·지연은 꺼진다. 큰 움직임은 페이드로 바뀐다(4장).

## 7. 속도를 일정하게 느끼게 하는 규칙

같은 성격 안에서도 컴포넌트마다 빠르기가 다르게 느껴질 수 있다. 원인은 두 가지였고, 각각 규칙으로 막는다.

1. **목표가 바뀌는 움직임은 JS 스프링으로 만든다.**
   - **원인:** CSS 전환은 목표가 바뀔 때마다 속도 0에서 다시 출발한다. 스위치는 탭 한 번에 목표가 세 번 바뀌었다(누름 → 전환 → 눌림 해제). 진행 막대는 값이 들어올 때마다 바뀐다.
   - **결과:** JS 스프링은 목표가 바뀌어도 속도를 이어간다. 진행 막대에 값이 연이어 들어올 때, CSS는 속도가 38%까지 떨어졌다가 다시 가속했다. JS 스프링은 105~118%를 유지했다(`tests/e2e/progress-tick.mjs`).
   - **해당 컴포넌트:** 스위치, 슬라이더, 세그먼트·탭 표시, 진행 막대.
2. **짧게 움직이는 것은 같은 성격의 더 빠른 스프링을 쓴다.**
   - **원인:** 스위치 손잡이는 약 20px, 세그먼트 표시는 약 90px을 움직인다. 같은 스프링이면 스위치가 4분의 1 거리를 같은 시간에 가서 굼떠 보인다.
   - **적용:** 스위치는 성격의 snappy 스프링을 앞쪽 끝 0.62배 응답 시간(감쇠 그대로, 넘침 비율이 같다), 뒤쪽 끝 0.82배 응답 시간에 감쇠 +0.05(최대 1)로 쓴다. 뒤쪽이 덜 넘쳐 물방울이 앞으로 늘어났다 모인다. 탭하는 순간 초기 속도도 준다. 손잡이가 끝에 닿는 순간을 감지해 그때 눌림 효과를 낸다.
   - **결과(lively):** 클릭 후 앞쪽 끝 도착이 153ms에서 약 90ms로, 손잡이 전체 정착이 237ms에서 약 150ms로 줄었다. 세그먼트는 90px 이동의 90% 지점까지 약 190ms다.

## 8. 깊이와 레이어

깊이는 세 가지를 따로 정한다. 하나의 숫자에 모두 담으면 새 컴포넌트에서 답이 갈린다.

1. **부위의 재질** — 컴포넌트 안의 각 부위가 홈인지, 표면인지, 볼록인지(8.1).
2. **고른 것의 표시** — 선택을 무엇으로 보여 주는지는 역할이 정한다(8.2).
3. **화면의 쌓임** — 바·패널·덮개가 어떤 순서로 겹치고 닫히는지(8.3).

**빛은 위에서 온다(고정).** 볼록한 것은 윗변이 밝고 아랫변이 그늘지며 아래로 짧은 그림자가 진다. 오목한 것은 안쪽 윗변이 그늘진다. 층이 높을수록 그림자는 더 멀리, 넓게 퍼진다(뜬 만큼 바닥에서 멀어진다). 움직이는 빛은 유리의 새틴 광택 하나뿐이고(1장), 테두리의 밝은 변·그림자 방향·볼록면의 광택은 포인터를 따라 돌지 않는다. 포인터가 없을 때(키보드·터치)와 동작 줄이기에서는 광택이 꺼지고 고정된 빛만 남는다.

### 8.1 층과 부위의 재질

| 층 | 이름 | 모습 | 토큰 | 부위 |
|---|---|---|---|---|
| −1 | 홈 | 안쪽 윗변이 그늘짐. 라이트: 옅은 채움 틴트. 다크: 주변보다 어두운 바탕에 아래 안쪽 가장자리가 살짝 밝음 | `--sg-groove`(레일) · `--sg-groove-soft`(입력란·세그먼트·스테퍼의 바탕) + `--sg-depth-inset` | **길**: 값이 움직이는 레일(스위치·슬라이더·진행 막대·막대 계기), 값이 들어가는 자리(입력란·검색란·콤보박스, 그리고 셀렉트·날짜·기간·시간 선택의 트리거 — 열어서 고르더라도 폼의 값을 담는 자리다), 세그먼트·스테퍼의 바탕, 기간의 띠. 축이나 눈금처럼 값이 지나가지 않는 선(구간 표시의 축)은 홈이 아니라 선이다. 체크박스·라디오의 빈 칸은 홈 대신 1.5px 테두리다 — 작은 칸이 비어 있음을 3 : 1 비텍스트 대비로 보여야 해서(옅은 홈 틴트로는 모자람) |
| 0 | 바탕 | 페이지 | `--sg-bg` | 배경 |
| 1 | 표면 | 아주 옅은 그림자나 머리카락 선. 다크에서는 바탕보다 한 단계 밝고 윗변에 빛 | `--sg-shadow-sm`, `--sg-separator`, `--sg-lit-edge` | 카드, 지표 카드, 목록 묶음(묶음 바탕 위에서는 색 차이로 충분), 표, 배너(상태 틴트) |
| 2 | 볼록 | 밝은 윗변, 그늘진 아랫변, 짧은 그림자 | `--sg-depth-raised` + `--sg-depth-raised-bg` + `--sg-depth-sheen` | **잡는 것**과 **고른 칸**(8.2): 세그먼트의 고른 칸, 휠 렌즈 |
| 2 | 손잡이 | 볼록과 같되 모든 테마에서 밝은 면 | `--sg-depth-raised` + `--sg-depth-handle-bg`, `--sg-depth-raised-edge` | 레일 위를 달리는 손잡이(스위치·슬라이더). 빈 레일과 강조색 채움 양쪽에서 떨어져 보여야 하므로 다크에서도 밝다 |
| 2 | 강조색 구슬 | 볼록 + 강조색 | `--sg-depth-raised-accent`, `--sg-depth-sheen-accent` | 고른 값(날짜·월·연도·요일·기간의 양 끝) |
| 3 | 떠 있는 유리 | 새틴 유리(1장), `--sg-shadow-md` | `.sg-glass` (`level="float"`) | 앱 바, 탭 바, 사이드바, 메뉴, 팝오버, 셀렉트 목록, 날짜·시간 패널, 토스트, 슬라이더 값 말풍선. 툴팁(차트 포함)은 떠 있지만 작고 잠깐이라 블러 없이 불투명한 작은 카드(`--sg-bg-elevated` + `--sg-shadow-md`)다 |
| 4 | 덮개 | 화면 전체(떠 있는 유리까지)를 어둡게 덮은 위에 올라오는 유리, `--sg-shadow-lg` | `.sg-glass--overlay` (`level="overlay"`) | 시트, 대화상자, 액션 시트. 미디어 뷰어는 화면 역할이라 자체 배경 |

- **부위를 정하는 규칙:** 입력하거나 고른 값이 들어가는 자리와 값이 움직이는 길은 홈(−1), 누르면 일을 하는 버튼(메뉴를 여는 버튼, 강조색 버튼 포함 — 강조는 색이 말한다)은 평평한 채움, 볼록(2)은 손잡이와 지금 고른 것을 표시하는 것에만 쓴다. 표의 행에 붙는 인라인 셀렉트(바탕 없음)와 필터 셀렉트(윤곽선 알약)는 폼의 칸이 아니라 행·막대 안의 작은 선택기라 예외다.
- **홈 모양은 고를 수 있다:** `createTheme({ grooves: 'flat' })`이면 홈(−1)이 같은 자리에서 안쪽 그늘 없는 평평한 틴트(각 테마의 채움)가 된다. 바뀌는 것은 홈뿐이고 손잡이·유리·그림자는 그대로다. 안쪽 테마는 따로 정하지 않으면 바깥 설정을 물려받고, 고대비에서는 어느 쪽이든 홈의 1px 윤곽선을 유지한다(가는 레일의 3 : 1 경계).
- **표면은 마우스를 올려도 표면이다:** 누를 수 있는 카드는 마우스를 올리면 살짝 밝아질 뿐 떠오르지 않는다(층이 바뀌는 것은 덮개가 열릴 때뿐). 배너·테두리 카드도 표면이라 다크의 윗변 빛과 고대비의 윤곽선을 받는다.
- **다크에서는 빛으로 높이를 말한다:** 어두운 바탕에서는 그림자가 거의 보이지 않으므로, 높이 있는 것일수록 밝고(바탕 → 표면 → 볼록 → 유리), 올라온 것(1·3·4층, 그림자 토큰)은 윗변에 고정된 빛을 받은 가는 선(`--sg-lit-edge`)이 있다. 홈은 반대로 주변보다 어둡다. 라이트에서는 `--sg-lit-edge`가 없고 그림자가 높이를 말한다.
- **유리의 농도와 높이는 따로:** `variant`(regular · strong · subtle · clear)는 얼마나 진한지(읽기 쉬움)만, `level`은 얼마나 떠 있는지(그림자)만 정한다. 메뉴는 진한(strong) 떠 있는 유리(3), 시트는 진한 덮개 유리(4)다.
- **볼록한 것은 홈이나 표면 위에만:** 유리(3·4) 위에는 볼록한 칩을 올리지 않는다. 유리 바 위의 선택은 평평한 틴트다(8.2). 예외: 고른 값 자체를 표시하는 것(날짜·기간 패널의 강조색 구슬, 시간 패널의 휠 렌즈)은 떠 있는 패널 안에서도 8.2의 볼록을 유지한다 — 여러 칸 중 고른 값을 짚는 표시이지 바의 선택이 아니다.
- **누르면 들어감:** 눌린 것은 0.965배로 표면 쪽으로 들어간다(1장 '눌림').
- **움직임은 층을 바꾸지 않는다:** 물방울과 피어남은 같은 층 안에서 일어난다. 층이 바뀌는 것은 덮개가 열릴 때뿐이다.

### 8.2 고른 것의 표시 — 역할이 정한다

| 역할 | 표시 | 예 | 고대비 |
|---|---|---|---|
| 길 위를 움직이는 선택 | 홈 위의 볼록 칸(물방울로 이동) | 세그먼트, 휠 렌즈 | 1.5px 윤곽선(`--sg-depth-raised`가 바뀜) |
| 유리 바 안의 선택 | 평평한 틴트. 하나로 이어진 레일(탭 바)에서는 물방울로 이동하고, 머리글과 스크롤로 끊기는 목록(사이드바)에서는 제자리에서 바뀜 | 탭 바, 사이드바 | 틴트 대신 윤곽선 |
| 고른 값 | 강조색 구슬 | 날짜, 월·연도 칸, 요일, 기간의 양 끝, 페이지 이동의 현재 페이지 | 강조색 채움 그대로(대비 검사 통과 색) |
| 범위 | 홈 안의 옅은 강조 틴트 | 기간의 사이 날짜 | 홈 윤곽선 |
| 현재 위치 | 밑줄이나 점 | 탭(밑줄), 페이지 점, 달력의 오늘(점) | 같음(선이 곧 표시) |
| 경로의 끝 | 굵기와 진한 글자(`aria-current="page"`) | 브레드크럼의 마지막 항목 — 맨 끝이라는 자리가 이미 지금 위치를 말하므로 점이나 밑줄을 더하지 않는다 | 같음 |
| 목록에서 고른 항목 | 체크 표시(표는 체크 칸 + 옅은 강조 틴트) | 선택 목록, 메뉴·셀렉트 항목, 표의 행 | 같음 |
| 켜짐 | 길(레일·상자)이 강조색으로 참 | 스위치, 체크박스, 라디오 | 같음(대비 검사 통과 색) |

새 컴포넌트는 위 표에서 역할을 고르면 표시가 정해진다. 키보드 포커스는 어느 표시와도 겹쳐 보이도록 따로 외곽선으로 그린다(4장).

### 8.3 화면의 쌓임

| 순서 | 무엇 | z 토큰 |
|---|---|---|
| 1 | 내용 | `--sg-z-base` |
| 2 | 떠 있는 바(앱 바·탭 바) | `--sg-z-bar` |
| 3 | 포털로 뜨는 것 전부(메뉴, 팝오버, 셀렉트, 날짜·시간 패널, 시트, 대화상자, 액션 시트) | `--sg-z-dialog` |
| 4 | 토스트 | `--sg-z-toast` |

- **포털끼리는 연 순서:** 같은 높이의 포털이 열린 순서대로 문서 끝에 붙으므로 **나중에 연 것이 위**다. 대화상자에서 연 메뉴는 대화상자 위에 뜬다.
- **Esc는 맨 위부터:** 열린 층을 쌓아 두고(`core/overlay` 의 층 스택) Esc는 맨 위 하나만 닫는다. 모달(대화상자·시트)이 하나라도 열려 있으면 뒤 페이지의 스크롤을 잠근다.
- **덮개는 아래를 모두 덮는다:** 시트·대화상자의 어둡게 덮는 막은 떠 있는 바까지 덮는다(4층이 3층을 이긴다).

### 8.4 대표 구성 — 화면에 유리를 어디에 두나

떠 있는 유리는 이 라이브러리의 재질을 보여 주는 가장 강한 수단이라, 한 화면에 몰아 두면 재질보다 특정 플랫폼의 구성이 먼저 읽힌다. 그래서 기본 구성은 아래와 같다.

- **떠 있는 바는 한 화면에 하나:** 아래 탭 바가 떠 있으면 위 바는 화면에 붙은 불투명 바(`AppBar attached`), 위 바가 떠 있으면 아래에는 떠 있는 바를 두지 않는다.
- **데스크톱·정보가 많은 화면:** 위 바는 붙은 불투명 바, 내용은 불투명 카드(표면 1층), 유리는 떠오르는 것(메뉴·팝오버·셀렉트·날짜 패널·토스트)과 덮개(시트·대화상자)에만 쓴다. 문서의 '대시보드' 예제가 이 구성이다.
- **화면 외곽에 맞추지 않음:** 떠 있는 바는 화면 모서리와 같은 중심을 맞추지 않는다(9장 6번).
- **큰 제목과 물방울 선택 이동은 쓸 수 있는 패턴이지 기본 화면의 조합이 아니다:** 대표 예제(쇼케이스)는 떠 있는 탭 바 하나에 붙은 위 바를 쓴다.

### 8.5 고대비

깊이 토큰은 모두 윤곽선이 된다(홈은 1px `--sg-separator-strong`, 볼록은 1.5px `--sg-label`). 표면(1층: 카드, 지표 카드, 목록 묶음)은 `--sg-surface-outline`으로 1px 테두리를 갖는다. 유리의 결과 광택은 꺼지고 테두리는 1.5px 단색이 된다. 위 8.2 표의 '고대비' 열이 각 선택 표시의 대체 모습이다.

### 8.6 컴포넌트 메모

- **휠:** 열 뒤에는 바탕을 두지 않고(놓인 표면 그대로), 렌즈만 볼록(2) — 세그먼트의 고른 칸과 같은 표면(`--sg-depth-raised-bg`: 라이트는 표면색, 다크는 한 단계 밝은 채움)이다. 줄이 렌즈 아래로 지나가고, 렌즈 안의 줄은 제 색에 조금 크게(1.14배), 멀어지는 줄은 작아지고 옅어진다. 멈출 때는 스크롤 스냅 대신 성격의 스프링이 가까운 줄을 렌즈로 끌어당긴다.
- **휠 렌즈의 모션(스위치와 같은 언어):** 손으로 돌리는 동안 줄이 가는 쪽 반대 가장자리가 들어와 렌즈가 그쪽으로 오므라들고(폭은 살짝 넓어짐), 줄이 렌즈를 지날 때마다 그 가장자리가 조금 더 눌린다(틱). 줄이 멈추면(60ms) 그 가장자리가 pop 스프링으로 튀어나왔다가 제자리로. 한 칸만 돌려도 같은 동작(최소 110ms 유지). 입력이 아니라 줄의 실제 움직임에 답한다 — 끝에서 더 밀어 줄이 안 움직이면 렌즈도 가만히 있고, 마지막 줄을 끌어당기는 스프링은 오므라듦을 이어 줄 뿐 새로 시작하지 않는다. 차분(squash 0)·동작 줄이기에서는 없음.

## 9. 모서리

반경은 크기가 아니라 **역할**로 정하고, 상자 안의 상자는 **같은 중심**을 갖게 한다. 문서 앱의 재질 페이지에 예시가 있고, e2e `corners`가 모든 문서 페이지에서 확인한다.

| 역할 | 토큰 | 값 | 예 |
|---|---|---|---|
| 표시 | `--sg-radius-mark` | 3 | 범례 견본, 글자 자리 표시(스켈레톤 줄) 같은 12px 미만의 표시 |
| 아주 작은 것 | `--sg-radius-xs` | 6 | 표 셀 강조, 포커스 테두리, 체크박스, 스켈레톤 |
| 작은 컨트롤 | `--sg-radius-sm` | 9 | 달력 칩, 작은 버튼, 목록 앞 아이콘 타일 |
| 컨트롤 | `--sg-radius-md` | 12 | 버튼(큰 버튼도 — 크기는 높이·여백·글자가 말한다), 입력란, 세그먼트, 스테퍼, 격자 칸, 대화상자 아이콘 타일 |
| 카드 | `--sg-radius-lg` | 16 | 카드, 지표 카드, 배너, 목록 묶음, 메뉴, 휠의 열 |
| 바·패널 | `--sg-radius-xl` | 22 | 앱 바, 탭 바, 사이드바, 액션 시트, 날짜 패널 |
| 시트 | `--sg-radius-2xl` | 28 | 시트, 대화상자 |
| 캡슐 | `--sg-radius-full` | — | 칩, 토글, 배지, 진행 막대, 막대 계기, 탭 밑줄, 기간 띠 |

모서리마다 그 모서리에서 만나는 두 변의 간격(가로 gx, 세로 gy)을 먼저 재고, 아래 순서로 정한다. 위에 있는 것이 이긴다.

1. **꽉 차면 바깥이 자른다(g = 0):** 간격 없이 붙는 것(카드의 사진)은 반경을 주지 않고 바깥이 잘라낸다(`overflow: hidden`이나 `clip`).
2. **같은 중심(0 < g < R, gx = gy):** 안쪽 반경은 **R − g**다. 두 테두리 사이의 띠가 모서리에서도 같은 두께로 이어진다. 예: 탭 바 22 − 5 = 17, 메뉴·셀렉트 목록 16 − 6 = 10, 액션 시트 22 − 6 = 16, 세그먼트 12 − 3 = 9, 스테퍼 12 − 2 = 10, 시간 패널 22 − 6 = 16(휠).
   - **최소 4px:** R − g가 4보다 작으면 4px을 쓴다(곡선이 바늘처럼 날카로워지지 않게). 이때만 2px을 넘는 어긋남(최대 4px)을 허용한다.
3. **멀리 있으면 자기 역할대로(g ≥ R):** 곡선이 서로 보이지 않으므로 안쪽은 자기 역할의 반경을 쓴다. g가 R을 넘는 순간 반경이 바뀌므로, 같은 중심을 노린 부품은 g를 R보다 충분히 작게 둔다.
4. **간격이 축마다 다르면(gx ≠ gy) 같은 중심이 아니다:** 한쪽 변에만 붙거나 가운데 놓인 것은 자기 역할의 반경을 쓴다. 휠 렌즈는 좌우만 4px 들어가 있고 위아래로는 가운데 있으므로 같은 중심 대상이 아니며, 컨트롤 반경 12를 쓴다(16 − 4와 같은 값이라 CSS는 부모에서 계산한다).
5. **안쪽이 정해진 모양이면 바깥을 맞춘다:** 안쪽 치수가 고정된 경우(캡슐 스위치)에만 바깥 = r + g로 역산하고, 이때는 바깥의 역할 반경보다 이것이 우선한다. 캡슐 스위치(높이 24) 옆에 간격 8을 두는 막대는 12 + 8 = 20.
6. **화면에는 맞추지 않는다:** 화면 역할을 하는 영역(내비게이션 스택, 미디어 뷰어, 앱의 창)의 모서리에 떠 있는 바를 맞추지 않는다. 기기마다 화면 모서리가 다르고, 화면과 같은 중심을 맞추는 것은 특정 플랫폼의 문법이다. 떠 있는 바는 자기 역할의 반경(22)을 쓴다.

- **CSS는 한 곳에서:** 바깥이 `--_radius`(반경)와 `--_nest`(안쪽 간격)를 선언하고, 안쪽은 `calc(var(--_radius) - var(--_nest))`를 쓴다. 패딩도 `--_nest`를 쓰므로 바깥의 반경이나 간격만 바꾸면 안쪽이 따라온다(세그먼트, 스테퍼, 탭 바, 메뉴, 셀렉트 목록, 액션 시트, 휠). 고정 토큰에서 직접 빼는 `calc(var(--sg-radius-lg) - 6px)` 꼴은 쓰지 않는다.
- **허용 오차:** 구현과 검사에서 2px까지는 같은 것으로 본다(눈으로 구분되지 않음). 표의 셀(내용), 화면 역할을 하는 영역과 문서의 무대(예시 틀, 휴대폰 모형)는 검사하지 않는다.
